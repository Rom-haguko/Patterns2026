# Patterns2026 — Автоматизация сети ресторанов

Программный комплекс для информационной системы сети ресторанов (лабораторный практикум по шаблонам проектирования).

## Архитектура проекта

Проект организован в соответствии с принципами чистой архитектуры (Clean Architecture) и предметно-ориентированного проектирования (DDD):

- `src/core/` — базовые абстракции, общие валидаторы и исключения (`abstract_model`, `abstract_manager`, `abstract_report`, `abstract_report_factory`, `abstract_converter`, `abstract_converter_factory`, `file_path_resolver`, `arguments_exception`, `operation_exception`).
- `src/models/` — доменные модели сущностей предметной области.
- `src/dtos/` — объекты передачи данных и перечисления (`report_data_dto`, `report_result_dto`, `report_type_enum`).
- `src/logics/` — сервисы бизнес-логики, менеджеры хранения и настроек, фабрики и конверторы.
- `Tst/` — набор модульных и интеграционных тестов.

## Доменные сущности

| Модель | Назначение |
|---|---|
| `abstract_model` | Базовый класс доменных сущностей с уникальным идентификатором `id` и именем `name`. |
| `range_model` | Единица измерения с поддержкой коэффициентов пересчета к базовой единице (`грамм`, `килограмм`, `миллилитр`, `литр`, `штука`). |
| `nomenclature_group_model` | Категория номенклатуры (`Сырьё`, `Полуфабрикаты`, `Готовая продукция`, `Упаковка`). |
| `nomenclature_model` | Номенклатурная позиция со ссылкой на группу, единицу измерения и связанный рецепт полуфабриката. |
| `storage_model` | Склад с наименованием и физическим адресом. |
| `organization_model` | Карточка организации с реквизитами (ИНН, БИК, расчетный счет, корр. счет, форма собственности). |
| `settings_model` | Модель системных настроек компании и формата отчетов по умолчанию. |
| `recipe_model` | Технологическая карта (рецепт) с рекурсивным расчетом Брутто/Нетто («блюдо в блюде»), списком строк и шагов приготовления. |
| `recipe_row_model` | Строка спецификации рецепта (номенклатура, вес брутто, вес нетто, единица измерения). |
| `recipe_step_model` | Технологический шаг приготовления с описанием и временем выполнения. |

## Подсистемы

### 1. Менеджер настроек и хранилище данных
- `settings_manager` (Singleton) — загрузка конфигурации из `settings.json`, валидация реквизитов и формата ответа.
- `storage_manager` (Singleton) — кеш данных в памяти с автоматической инициализацией первичных справочников при первом старте.

### 2. Подсистема сериализации
- `abstract_converter` / `abstract_converter_factory` — контракт конверторов и фабрики.
- `basic_convertor`, `datetime_convertor`, `reference_convertor` — сериализация примитивов, дат и ссылочных моделей с защитой от циклических ссылок.
- `convert_factory` — сопоставление типов данных с реализациями конверторов.
- `json_serializer` — преобразование доменных объектов в JSON-представление и запись в файлы.

### 3. Подсистема отчетов
- `abstract_report` / `abstract_report_factory` — базовые абстракции генерации отчетов.
- `report_data_mapper` — вынос логики маппинга доменных сущностей в транспортный DTO (`report_data_dto`) с сохранением чистоты моделей.
- `text_report`, `csv_report`, `markdown_report`, `xml_report`, `html_report` — полиморфные генераторы отчетов в 5 форматах.
- `report_service` — сервисный слой для работы с отчетами и отдачи HTTP-ответов.
